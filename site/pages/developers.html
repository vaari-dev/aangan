Principles

  • No dependencies. Only the Android framework and org.json; even the QR encoder is ours.
  • No work while you watch. Nothing animates on an ordinary day; scenes, the focus glow and the network run only while the home screen is showing.
  • No data leaves the TV except requests to Open-Meteo. A new kind of request needs a privacy-policy change first.
  • Drawn, not downloaded. Scenes, icons and the logo are code or vectors, so the app is about 150 KB.
  • Readable over clever.

Building

JDK 17+ and the Android SDK (ANDROID_HOME, or sdk.dir in local.properties).

git clone {{REPO}}
cd aangan
./gradlew assembleDebug    # app/build/outputs/apk/debug/aangan-debug.apk
./gradlew installDebug     # and install it over adb (set ANDROID_SERIAL with several devices)
./gradlew check            # unit tests, Android Lint and javac warnings

Every warning is an error. CI also runs emulator smoke tests and CodeQL. Preview a scene:

adb shell am start -n dev.vaari.aangan/.HomeActivity --es festival Diwali

Any calendar name works, or a family day such as "Asha's birthday". Home clears it.

Releases

Signed with the project's key:

AANGAN_KEYSTORE=~/keys/aangan-release.jks AANGAN_KEY_PASS=… ./gradlew assembleRelease bundleRelease

Output: app/build/outputs/apk/release/aangan-release.apk and app/build/outputs/bundle/release/aangan-release.aab, shrunk with R8. Without those variables they're debug-signed and can't update a real install.

The same key signs GitHub releases and Google Play, so either can update the other. To release, raise versionCode and versionName in app/build.gradle.kts, add a CHANGELOG.md section, and push to main; an owner approves the release.

The festival calendar

app/src/main/assets/festivals.csv has one line per festival day:

# date,name,greeting,scene[,expected]
2026-11-08,Diwali,Happy Diwali,DIWALI
2027-03-10,Eid al-Fitr,Eid Mubarak,EID,expected
  • scene is a name from Festive.Theme, or PLAIN for the greeting alone.
  • expected marks a date that depends on a moon sighting.
  • Days between two entries with the same scene, up to nine days apart, share it.
  • Dates follow Drik Panchang for New Delhi; national days and Eid, the Government of India's list.
  • Families' moves and hides are keyed by the original date and name, so changing either drops them.

The festival page is generated from this file.

Adding a scene

  1. Add a value to Festive.Theme with its glow and accent colours.
  2. Add a case to the drawing switch in Festive, from existing pieces (stars, moon, diyas, lights, toran…) or a new method.
  3. Time it with part() for the opening and sway(), flicker() for the loop. Keep the clock, date, weather pill and tiles clear.
  4. Use the scene in festivals.csv, preview it with am start … --es festival, and add it to SCENES in tools/site.py.

Security model

The phone setup page

  • Lifetime: a server socket on port 8737 (or any free port) opens in SetupActivity.onResume and closes in onPause.
  • Authorisation: every path is under a 10-character SecureRandom secret from a 32-letter alphabet (50 bits), new each time Settings opens and shown only on the TV. Anything else gets a bare "link expired" page.
  • Input: names are capped at 40 characters; dates are validated, and festival moves limited to a year either side. All output is HTML-escaped.
  • Reach: it listens only on the TV's home-network address, not every interface (a VPN, a public IPv6 address), and refuses requests naming any other host, which stops DNS rebinding.
  • Limits: request line and headers 8 KB, body 8 KB, whole request within 10 seconds. City searches are capped at 100 characters and cached. A city from the phone needs real coordinates and a known time zone; at most 200 family days.
  • Headers: Cache-Control: no-store, Referrer-Policy: no-referrer, X-Content-Type-Options: nosniff, and a CSP allowing only the TV's own resources, forms and requests. No cookies.
  • Script: one small file, for city suggestions and the dock. It uses textContent, never HTML, and the page works without it.
  • Transport: plain HTTP; the network is assumed trusted. Someone watching it during setup could see what's entered, but not reach the page later.

The Home-button service

  • Consumes KEYCODE_HOME only; every other key passes through.
  • Window events are limited by android:packageNames to the stock launchers (Google TV, Android TV, Leanback, PatchWall).
  • canRetrieveWindowContent="false".
  • It starts Aangan's activity and nothing else.

Network

  • usesCleartextTraffic="false".
  • Coordinates are rounded to two decimals.

Report problems privately through GitHub's vulnerability reporting.

Icon and website

  • python3 tools/icon.py draws the icon and banner (res/drawable/icon.xml, banner.xml and the SVGs). The wordmark is Fraunces, as a path in tools/wordmark.txt.
  • python3 tools/site.py builds this site into build/site/; CI publishes it on every push to main.

Contributing

  • Open an issue first for anything large.
  • Keep to the principles above and match the surrounding code.
  • Test on a real TV if you can, and say which.
  • ./gradlew check must pass. Details, including translating, in CONTRIBUTING.md.
